## 2. Recurring bug patterns

These root causes produce several findings each. Fixing a pattern once is cheaper and stops
the next instance.

1. **Caches keyed on `doc.id` instead of the page list.** Read aloud (UI-1), Reflow (X-11)
   and Compare (X-13) cache bytes or text per document id. Any page edit leaves them
   stale, and they serve deleted pages. → Add a `pagesVersion` (or use the `doc.pages`
   identity) to every per-document cache key.
2. **"Never larger than the input" is enforced tool by tool, not centrally.** Compress
   guards it. Image to size guards it only for upright JPEGs (IMG-1). Grayscale only
   warns (UI-OPS19). Compress + Protect skips the guard (IMG-5). → Add one
   `chooseSmaller(original, result)` helper in the commit path for every size-reducing
   tool.
3. **Success copy comes from intent flags, not from the final bytes.** Compress
   "Reached" ignores Protect's overhead (IMG-5). Repair's "Opened X" ignores
   `addDocument() === false` (RT-2). Image to size "Reached" uses a re-encode that grew.
   → Compute every success message from the bytes that are actually saved and the
   return value that was actually received.
4. **Verification skips the fallback path.** Grayscale verification ignores pages it
   rasterised (PDF-2). The encryption check reads only the trailer, which is exactly what
   a damaged file loses (PDF-1). Repair salvage scans stream data in a file that is not
   damaged (PDF-3). → Verify the output, not the plan. Gate risky recovery on evidence of
   damage.
5. **Two parsers for one input.** The watermark preview and the worker parse page ranges
   differently (X-7). Split points use a third, looser parser (X-8). → Use one exported
   `parsePageRange`, and warn when a non-empty range selects zero pages.
6. **Ad hoc byte units.** `formatBytes` became 1000-based, but split-by-size, Local
   data, import, OCR and the zip guard still use 1024 (IMG-4, X-10). Rounding hides
   overshoots (IMG-3). → One decimal formatter and parser. Round up when showing a size
   that missed its target.
7. **Whole-document-in-memory loops.** Grayscale holds every page's raster (PDF-5).
   Redline holds every page of both documents (X-5). Visual diff reloads both documents
   on every page (X-4). → Work in page batches and load each document once.
8. **A rejected promise or `onerror` leaves the UI stuck.** Read aloud has no
   `utterance.onerror` (UI-2). Reflow, `HomeView` and `LocalDataSection` have no
   `.catch` (X-11). The Flate writer rejections are unhandled (X-12). → Every async UI
   effect needs an error state. Lint for floating promises
   (`@typescript-eslint/no-floating-promises`).
9. **Hard-coded English outside `t()`.** About 15 progress labels in `operations.ts` and one
   `HomeView` detail (X-14, UI-12). The i18n coverage test only sees `t()` calls. →
   Extend the coverage scan to string literals passed to `stage()`/`progress()`/`detail`.

## 3. Findings

### PDF internals (OPS-19 grayscale, DOC-13 repair, OPS-20 duplex)

- **PDF-1 🟠 High [probe]** — `src/core/pdf/repair.ts:565`
  - **Defect:** the only encryption check is `doc.isEncrypted`, which comes from the
    trailer's `/Encrypt`.
  - **Failure:** an encrypted PDF cut before its final `xref` loses its trailer. Repair
    "rebuilds" it and reports success. The output has no `/Encrypt`, and every string and
    stream is still ciphertext.
  - **Fix:** also refuse when any indirect dict has `/Filter /Standard` with `/O` and
    `/U`, or when the raw bytes contain `/Encrypt`.
- **PDF-2 🟠 High [probe]** — `src/core/operations.ts:3078`,
  `src/core/workers/render.worker.ts:2014`, `src/core/pdf/grayscale.ts:1311`
  - **Defect:** a page is rasterised when an annotation appearance can't be converted.
    That render uses `annotationMode: DISABLE`, so the original colour annotation stays
    on top. `colourLeft` ignores raster reasons, so the save goes through.
  - **Failure:** before and after, max pixel chroma is 255.
  - **Fix:** count `rasterReasons` as colour left, or flatten the annotations into the
    raster and drop them.
- **PDF-3 🟡 Medium [probe]** — `src/core/pdf/repair.ts:211-262`
  - **Defect:** `salvageDroppedObjects` regex-scans stream bytes for `N G obj`.
  - **Failure:** an intact PDF that contains that text in a content stream or an
    uncompressed EmbeddedFile is reported as damaged, and a foreign object 99 is
    injected. Where the numbers collide, real objects can be replaced.
  - **Fix:** salvage only when the xref is bad or `%%EOF` is missing, and skip matches
    inside parsed stream ranges.
- **PDF-4 🟡 Medium [probe]** — `src/core/pdf/functions.ts:139-143`
  - **Defect:** a Type 0 function with more than one input uses nearest-neighbour
    lookup instead of multilinear interpolation.
  - **Failure:** DeviceN tints come out as the wrong greys, with hard jumps at
    (0.5, 0.5).
  - **Fix:** interpolate, or return null (rasterise) when m > 1.
- **PDF-5 🟡 Medium [read]** — `src/core/operations.ts:3003-3046`
  - **Defect:** the decoded images and rasters for every page are held at once.
  - **Failure:** a 300-page 300 dpi scan needs about 2.5 GB in the render worker, then
    a copy into the process worker, so the tab runs out of memory.
  - **Fix:** plan, decode and apply in page batches.
- **PDF-6 ⚪ Low [probe]** — `grayscale.ts:1047`
  - **Defect:** a resource-less shared Form XObject is converted separately on every
    page.
  - **Failure:** one form becomes N copies, so the output is bigger than needed.
  - **Fix:** memoise by object plus inherited resources.
- **PDF-7 ⚪ Low [probe]** — `functions.ts:269-272, 586`
  - **Defect:** a PostScript stack underflow returns 0 instead of failing.
  - **Failure:** a malformed tint maps to the wrong grey instead of being rasterised.
  - **Fix:** throw on underflow, and return null rather than zeros.
- **PDF-8 ⚪ Low [read]** — `grayscale.ts:910-913`
  - **Defect:** every content-parse error is reported as "contains an inline image".
  - **Fix:** choose the message from the error.
- **PDF-9 ⚪ Low [read]** — `render.worker.ts:2003`, `repair.ts:213,507`
  - **Defect:** `renderPageGray` takes no job handle, so it can't be cancelled, and
    repair builds two whole-file latin1 strings.
  - **Fix:** pass the job handle through, and scan the bytes directly.

### Runtime and storage (DOC-14, DOC-15, DS-12)

  - **Fix:** add a per-session flag.
- **RT-10 ⚪ Low (hygiene) [probe]** — eight `*.orig` files are tracked:

  - tsc, eslint, vitest, prettier and the bundle all ignore them.
  - Every live file is a superset of its `.orig`, so no code was dropped.

  - **Fix:** `git rm` them and add `*.orig` to `.gitignore`.

### Platform and distribution (DIST-06, DIST-07, DIST-08)

- **PLT-1 🟠 High [probe]** — `src/platform/pwa/service-worker.ts:137-149`,
  `vite.config.ts:379`
  - **Defect:** pages are fetched network-first, but entry scripts are unhashed
    (`[name].js`) and served cache-first.
  - **Failure:** after a deploy, F5 runs v2 HTML with v1 `editor.js`. v1's worker also
    caches the v2 HTML, which breaks the next offline launch. This contradicts DIST-06's
    "never swaps code under an open document".
  - **Fix:** hash the entry file names, or serve pages cache-first from the controlling
    worker's own cache.
- **PLT-2 🟡 Medium [probe]** — `vite.config.ts:173-190`, `scripts/csp.mjs`
  - **Defect:** the web build's CSP is a `<meta>` tag, which doesn't apply to workers.
    GitHub Pages sends no CSP header.
  - **Failure:** a `fetch` inside a worker reaches the network on the website, but not in
    the extension.
  - **Fix:** add a network guard in each worker entry, or host somewhere that can send
    response headers. At minimum, document the gap.
- **PLT-3 🟡 Medium [probe]** — `src/platform/pwa/sw-routing.ts:320`,
  `service-worker.ts:165-175`, `src/ui/pwa.ts:259-273`
  - **Defect:** any website can auto-submit a form to `/share-target`.
  - **Failure:** an attacker-chosen PDF opens automatically in the workspace (a
    social-engineering lure, and a way to flood storage).
  - **Fix:** reject requests where `Sec-Fetch-Site` is `cross-site` or the referrer is a
    foreign origin. Check first what a real Android share sends.
- **PLT-4 🟡 Medium [read]** — `service-worker.ts:130-134`, `src/platform/pwa/register.ts:137-143`
  - **Defect:** applying an update in tab A deletes the old cache, but only tab A
    reloads.
  - **Failure:** tab B can no longer load its tool code (it 404s or fails offline).
  - **Fix:** broadcast a reload to all clients, or keep the old cache until its clients
    are gone.
- **PLT-5 ⚪ Low [read]** — `src/platform/pwa/share-inbox.ts:39-61`, `src/ui/clearLocalData.ts`
  - **Defect:** shared files can stay in the `stapler-share-inbox` cache indefinitely,
    and Clear-all doesn't delete it.
  - **Fix:** add `caches.delete(SHARE_INBOX_CACHE)` to Clear-all, and age out stale
    batches.
- **PLT-6 ⚪ Low [read]** — `service-worker.ts:143`
  - **Defect:** the network-first page fetch has no timeout.
  - **Failure:** on a flaky connection, offline launch stalls until the browser gives up.
  - **Fix:** a timeout of about 3 s, or cache-first (see PLT-1).
- **PLT-7 ⚪ Low [read]** — `.github/workflows/release.yml:91-124`
  - **Defect:** the release job rebuilds instead of shipping the tested artifacts, and
    `perf` is not in `needs`.
  - **Fix:** build once, upload an artifact, and have the test and publish jobs consume
    it.

### Image tools (CNV-14, DIST-08)

- **IMG-1 🟠 High [probe]** — `src/ui/tools/commit.ts:1172-1181`, `src/core/image-target.ts:151`
  - **Defect:** the keep-original fallback applies only to upright JPEGs.
  - **Failure:** with a 5 MB target:

    - WebP: 488 → 3,002 B.
    - With no target, WebP still grows from 488 to 2,202 B.
  - **Fix:** for every format, keep the original when it already meets every limit and
    the result is not smaller.
- **IMG-2 🟡 Medium [read]** — `src/ui/tools/image-size/ImageSizePanel.tsx:124-136`
  - **Defect:** an out-of-bounds amount is dropped silently while the field still shows
    it, and changing the unit skips the bounds check.
  - **Failure:** type "4" KB and the run uses the previous 50 KB. Switching 0.5 MB to KB
    gives 500 B; switching 500 KB to MB gives 500 MB.
  - **Fix:** convert the amount on unit change, and show an inline validation error.
- **IMG-3 🟡 Medium [probe]** — `src/ui/components/Feedback.tsx:154-157`
  - **Defect:** `formatBytes` rounding hides overshoots, and 999,500–999,999 B shows as
    "1000 KB".
  - **Failure:** "Could not reach 200 KB. The smallest Stapler could make is 200 KB."
  - **Fix:** round up when showing a size that missed its target, and switch to MB at
    999,500 B.
- **IMG-4 🟡 Medium [read]** — `src/ui/tools/commit.ts:961`
  - **Defect:** split-by-size uses `targetSizeKb * 1024`.
  - **Failure:** "5000 KB" allows 5.12 MB parts, which fail a 5 MB portal limit.
  - **Fix:** use `* 1000`.
- **IMG-5 ⚪ Low [read]** — `commit.ts:1451-1452`
  - **Defect:** the Compress "Reached" toast ignores Protect's encryption overhead.
  - **Fix:** gate the toast on `finalSize <= targetBytes`.
- **IMG-6 ⚪ Low [probe]** — `src/core/workers/render.worker.ts:1281` with `offscreen()` at :530
  - **Defect:** "Longest side at most N" can give N+1 px, because of floating point and
    `Math.ceil`.
  - **Failure:** a 595 pt page gives 401, 801 or 1601 px.
  - **Fix:** size the canvas with `fitWithin`, or floor with an epsilon.
- **IMG-7 ⚪ Low [read]** — `src/ui/tools/convert/PdfToImagePanel.tsx:37-40`
  - **Defect:** the size estimate hard-codes a 595 pt width and caps the width rather than
    the longest side.
  - **Fix:** use the first page's rotated viewport.
- **IMG-8 ⚪ Low [plausible]** — `src/core/workers/image.worker.ts:124-129`
  - **Defect:** the `createImageBitmap` path has no `MAX_RASTER_PIXELS` check.
  - **Failure:** a 20000×20000 PNG gives a cryptic canvas or out-of-memory error.

- **IMG-9 ⚪ Low [read]** — `src/core/raster-decode.ts`, `image.worker.ts:126`
  - **Defect:** TIFF Orientation (tag 274) is ignored, and animated GIFs silently lose

  - **Fix:** apply the tag, and add a note when frames are dropped.
- **IMG-10 ⚪ Low [read]** — `src/core/image.ts:60-62`
  - **Defect:** `isBrowserRenderableImage` ORs the MIME type with the extension.
  - **Failure:** a HEIC file named `.jpg`, or a 0-byte `.png`, shows a broken `<img>`.
  - **Fix:** return false when `rasterKindOf()` is non-null or the size is 0, and add an

- **IMG-11 ⚪ Low [read]** — `image.ts:318,349`, `src/core/deep-link.ts:52`
  - **Defect:** the "200 MB" limit is actually 200 MiB, and "KiB"/"MiB" are parsed as

  - **Fix:** be consistent: use 200,000,000, and reject or correctly scale KiB/MiB.
- **IMG-12 ⚪ Low [read]** — `src/ui/tools/compress/CompressPanel.tsx:182-189`

## 5. Checked and found sound

- **Permissions:** every build ships `permissions: []`, with no host permissions and no
  content scripts. `omnibox` is a manifest key, not a permission. What's new uses
  IndexedDB, not `chrome.storage`.
- **Invariants:** the manifest CSP is identical to `STAPLER_CSP`. There is no `chrome.*`
  outside the allowed layers, no raw colours, and no network calls outside the
  allow-listed OCR and font files.
- **Deep links:** NaN, negative, huge and unknown values are rejected or clamped. Values
  reach only signals, never the DOM.
- **Worker client:** crashes and terminations reject pending calls, `pin()` and
  `release()` are balanced, and abort listeners are removed. No `ArrayBuffer` is reused
  after being transferred.
- **Document cap:** enforced on every external open path (drag-drop, share, Home, Folder
  search, paste).
- **Undo and redo** stay within the active document.
- **Object URLs** are revoked everywhere, and no `setInterval` is used.
- **Image to size:** the quality search is bounded, a miss is never reported as reached,
  and transparency becomes white in a JPEG.
- **Duplex interleave** ordering is correct for even, odd and mismatched counts.
- **Repair** opens truncated files and files with a bad `startxref` correctly.
- **Commit and CTA** have a double-run guard, `useJob` cleans up progress on error and
  cancel, and modal focus is handled correctly.
