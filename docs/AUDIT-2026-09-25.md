## 2. The recurring mistakes (root causes)

Most of the 98 findings come from **nine patterns**, several of which earlier audits also
hit. Fixing each pattern once, with a shared helper, a lint rule, or a test harness,
closes whole groups of bugs and stops them coming back.

### M1. A new `PDFObjectCopier` per page

> **Status:** ✅ Fixed — `src/core/pdf/rebuild.ts`
`copyPages(src, [i])` / `embedPage()` called in a loop builds a fresh copier every time.
pdf-lib then (a) duplicates every shared font or image per page and (b) makes an **orphan
copy of any page that something else points at** (annot `/P`, link `/Dest`, sibling
widget). That orphan keeps the original content stream.
**Causes:** PDF-1, PDF-6, PDF-7, PDF-11, PDF-12. AUDIT-FINDINGS §0 claimed this was fixed
for redaction; it is not (⟲).
**Fix once:** a single `rebuildDocument(src, pageIndices)` helper. It uses one copier,
pre-registers `srcPageRef → dstPageRef` before copying, remaps `/Dest`, `/GoTo` and `/P`,
nulls links to excluded pages, and sweeps unreachable objects. Ban direct
`copyPages`/`embedPage` in loops with a lint rule.

### M2. Geometry against the MediaBox instead of the visible CropBox

> **Status:** ✅ Fixed — `src/core/pdf/display-frame.ts`
The rotation half of AUDIT-FINDINGS §3 was fixed; the **origin/crop half** was not. Tools
map UI coordinates (pdf.js viewport = CropBox, rotated) onto `page.getSize()` (MediaBox,
unrotated, no origin).
**Causes:** PDF-8, PDF-9, PDF-10. This is the third time this class of bug has come up.
**Fix once:** a single `displayFrame(page)` built from `getCropBox()` ∩ MediaBox with
origin and rotation, used by every placement path, with one golden test per tool on a
rotated, cropped, offset-origin page.

### M3. Tool state in module-level signals that aren't keyed to a document

> **Status:** ✅ Fixed — `src/ui/tools/docScoped.ts`
Settings and results survive a document switch or edit, and export applies them to the
wrong document. AUDIT-FINDINGS §12 found and fixed this for three tools; the same pattern
remains in the others.
**Causes:** UI-1, UI-3, UI-11, UI-12, UI-18, UI-25. Also `redact/state.ts` already shows
the correct pattern (an `effect` on `activeDocId`).
**Fix once:** a `docScopedSignal(initial)` helper that tags a value with
`{docId, pagesVersion}` and returns `initial` when either changes. Add a unit test that
iterates every tool's state module.

### M4. Testing the web preview instead of the shipped extension

> **Status:** ✅ Fixed — CI runs on `master`, and Playwright `extension` projects test the real packaged build
Every e2e spec runs against `vite preview` (no MV3 CSP, `VITE_E2E_TEST_HOOKS=true`). CI
triggers on a branch that doesn't exist.
**Causes:** CONV-1 (HEIC), PLT-1/PLT-2/PLT-7, and earlier OCR-04 and SCN-04. Tickets
CNV-03, QA-03, QA-04, NFR-02, ACC-02 and DIST-03 are marked Done on the strength of this.
**Fix once:** a Playwright project that loads `dist/ext` via `--load-extension`
(confirmed working headless). Add "verified in the loaded extension" to the Definition of
Done for anything touching workers, WASM, or third-party decoders.

### M5. The "job running" lock covers only some mutators

> **Status:** ✅ Fixed — `src/ui/busy.ts` (call-site guard)
Only undo/redo, tab switching and the primary CTA check `activeJob`. Page delete, rotate,
reorder, paste, stamp, secondary buttons and imports don't.
**Causes:** RT-3, RT-5, RT-7, RT-8, UI-9, UI-20.
**Fix once:** enforce the lock **in the store mutators**, not at call sites. Route imports
through `useJob` so they are cancellable and set the lock. Make `run()` tell the user it
refused instead of silently returning `undefined`.

### M6. Garbage collection that ignores history and past sessions

> **Status:** ✅ Fixed — history-aware liveness, pending imports, startup OPFS sweep
`closeDocument` frees sources that only the undo stack references. Nothing ever sweeps
OPFS.
**Causes:** RT-2, RT-4, RT-5, RT-6, RT-14.
**Fix once:** compute liveness from live documents, the undo/redo snapshots, and pending
imports. Run a startup OPFS sweep after the recovery decision.

### M7. Verifiers that aren't independent of what they verify

> **Status:** ✅ Fixed — whole-file residual-text and orphan-page check; PDF-4 geometry now uses all four corners
The redaction verifier reads only page-tree text and recomputes the plan with the **same**
geometry code as the redaction.
**Causes:** PDF-1 and PDF-4 both report `verified: true` on leaking output.
**Fix once:** the verifier should (a) decode and scan **every** stream in the output for
the redacted strings, (b) assert that no `/Type /Page` exists outside the tree, and (c)
use an independent coverage check (render and diff, or four-corner quads).

### M8. Fixes tested without the downstream pipeline step

> **Status:** 🟨 Partly — every new regression test runs the default path through the real pipeline; not yet written into the Definition of Done
The OCG test never runs the mandatory scrub that follows redaction (PDF-5). The metadata
e2e always clicks Inspect first (UI-1). The HEIC e2e never sees the CSP (CONV-1).
**Fix once:** test **user flows end-to-end through the real pipeline**, including the
default path where the user doesn't click the optional button.

### M9. Invariants enforced by regex rather than by the runtime

> **Status:** ✅ Fixed — strict CSP in both builds, ESLint network-API ban
The hook misses about 25 of 30 network-call spellings and doesn't scan the root HTML.
Meanwhile the CSP, which would actually enforce the rules, has no `default-src` and
allows all of jsDelivr.
**Causes:** PLT-3, PLT-4, PLT-6, CONV-2.
**Fix once:** make the CSP the real guarantee (strict, path-scoped, in both builds). Use
ESLint `no-restricted-globals` for network APIs, and add a post-build grep of `dist/` for
hosts against an allowlist.

### 3.1 PDF internals (`process.worker.ts`, `core/pdf/*`)

#### PDF-1 · 🔴 Critical · Redaction leaves the unredacted page in the file, and verification passes — ✅ Fixed

> **Status:** One shared copier per rebuild with source→output page refs registered before copying (`src/core/pdf/rebuild.ts`), plus a whole-file residual-text and orphan-page check in the verifier. The audit probe now shows no leak in any variant.
- **Where:**
  - `src/core/workers/process.worker.ts:6156`: `out.copyPages(source,[i])` builds a copier per page.
  - `:7741`: the sweep keeps the orphan because it is reachable.
  - `render.worker.ts:1431`: the verifier reads only pages `1..numPages`.
- **Trigger:** redact text on a page that anything references: a sticky note's `/P`, a TOC link's `/Dest`, or a widget. Real Word/LaTeX/form PDFs always have these.
- **Impact:** the orphan page copy keeps the original `/Contents` (plus `/Thumb` and `/PieceInfo`). `strings`/qpdf recover the "redacted" text, including after the scrub step. The UI reports verified. **[probe]** All three variants leaked; the control case with no annotation did not.
- **Fix:** M1 single-copier rebuild, plus the M7 independent verifier.

#### PDF-2 · 🔴 Critical · "Embed missing font" (DOC-12) turns every run in that font into garbage — ✅ Fixed
- **Where:** `process.worker.ts:4406-4444` (`:4425`).
- **Cause:** `embedFont` produces `Type0/Identity-H` (2-byte CIDs), but the content keeps 1-byte WinAnsi codes, so "Hello" is read as CIDs 0x4865… and renders as `.notdef`. `/Widths` are lost too. The UI says "fixed".
- **Fix:** write a *simple* `/TrueType` font with the original encoding, `/FirstChar`/`/LastChar`/`/Widths` and `/FontFile2`. Re-extract the text after the change and return the original bytes if it differs. **[probe]**

#### PDF-3 · 🔴 Critical · Flatten background (OPS-13) leaves a dangling full-page path — ✅ Fixed
- **Where:** `process.worker.ts:4655-4660`.
- **Cause:** only the paint operator (`f`) is dropped; the `re`/`m`/`l` path construction stays. The next fill in the stream paints the whole page in its colour.
- **Input → output:** `1 1 0 rg 0 0 612 792 re f 0 0 0 rg 100 100 10 10 re f` becomes `… 0 0 612 792 re 0 0 0 rg 100 100 10 10 re f`, so the page is filled black.
- **Fix:** drop the whole path-construction run with its painter (the `currentPathStmts` pattern already exists in `filterContentStream`). **[probe]**

#### PDF-4 · 🟠 High · Images at a non-right-angle rotation escape redaction — ✅ Fixed
- **Where:** `src/core/pdf/interpreter.ts:1413-1446`. The image box is built from two diagonal corners only; at 45° it has zero width.
- **Impact:** the image is neither stripped nor pixel-redacted, only overlaid, and the verifier uses the same geometry so it passes.
- **Fix:** transform all four corners (as `formBoxOf` does) and test the quad, not its bounding box. **[probe]**

#### PDF-5 · 🟠 High · ⟲ REGRESSION: redaction's mandatory scrub strips `/OCProperties`, which un-hides hidden layers — ✅ Fixed
- **Where:** `src/core/operations.ts:989` calls `scrubMetadata(output, undefined)`; the defaults delete `/OCProperties` (`process.worker.ts:5914`).
- **Impact:** this undoes the 09-15 audit's OCG fix. Layers the author set OFF by default render and print in the "redacted" file. The OCG test doesn't run the scrub step.
- **Fix:** pass `hasOptionalContent: false` from redaction. When stripping OCProperties, also remove OFF-group content. **[probe]**

#### PDF-6 · 🟠 High · Every rebuild breaks internal links; Extract/Split ships pages the user excluded — ✅ Fixed
- **Where:** same root cause as PDF-1 (`:2423` compose, `:5326` compress, `:5961` scrub, `:6156` redact).
- **Impact:** extracting page 1, which links to page 3, put page 3's full text into the output **[probe]**. Merge, compress, scrub and watermark all silently kill TOC and footnote links.
- **Fix:** M1.

#### PDF-7 · 🟠 High · ⟲ REGRESSION: the redaction rebuild copies shared resources once per page (~10× size) — ✅ Fixed

> **Status:** `shared-image.pdf` redaction output is now 4.69 MB for a 4.68 MB input (was 46.8 MB). A text-only 100-page file still roughly doubles (75 KB → 150 KB); not investigated.
- **Where:** `process.worker.ts:6156`. AUDIT-FINDINGS §0 says redaction "shares one PDFObjectCopier"; it doesn't.
- **Measured:** `shared-image.pdf` 4.7 MB → **46.8 MB** **[probe]**. A 300-page document with a big font can crash the worker.

#### PDF-8 · 🟠 High · Raster compression ignores CropBox and a MediaBox origin offset — ✅ Fixed

> **Status:** Raster pages take their MediaBox/CropBox from the visible box (CropBox ∩ MediaBox, in the original user space), keep `/Rotate`, and place the raster at the crop origin — no stretching, and copied annotation `/Rect`s stay on the same content. Verified against the pdf.js viewport.

- **Impact:** a cropped scan is stretched, cropped margins come back, and annotations move **[probe]**. Cropped scans are the most common compression input.

#### PDF-9 · 🟠 High · Signatures/stamps and the crop tool place against the MediaBox, not the CropBox — ✅ Fixed

#### PDF-10 · 🟠 High · Annotate drawings (including whiteout) ignore `/Rotate` and CropBox — ✅ Fixed

### 3.2 Runtime: workers, store, history, storage

#### RT-1 · 🟠 High · A worker crash or failed boot hangs every in-flight call and every pinned render handle forever — ✅ Fixed
- **Where:** `src/core/workers/client.ts:107-123`; `render-cache.ts:147-168`; `useJob.ts:61`.
- **Cause:** Comlink 4.4.2 never rejects pending calls when the worker is terminated.
- **Impact:** `activeJob` stays set for good, so undo, tab close and every new job are dead and Cancel does nothing. Thumbnails for open documents hang. Only a reload recovers. A realistic trigger: a web-twin redeploy 404s the old hashed worker URL. This also corrects G4's wording: the lease doesn't reject, it hangs. **[probe]**
- **Fix:** race each call against an instance-death promise that the `error` handler rejects. Evict render handles owned by the dead instance.

#### RT-2 · 🟠 High · Closing any tab deletes bytes the undo stack still needs — ✅ Fixed
- **Where:** `src/core/store.ts:400-416`. `stillUsed` is built from current pages and baseline only; `historySourceRefCount` exists but is never used.
- **Trigger:** redact doc A (old source now referenced only by undo), close doc B, press Ctrl+Z on A.
- **Impact:** A points at deleted bytes, so thumbnails go blank and export fails. The broken state is autosaved and restored on the next launch. **[probe]**
- **Fix:** M6. Include every snapshot's pages and baseline in liveness, and validate every `sourceDocId` in `checkRecovery`.

#### RT-3 · 🟠 High · Deleting a document's last page(s) closes it: no confirmation, no undo, bytes gone — ✅ Fixed

> **Status:** Fixed differently from the suggestion: deleting every page is **refused** with a message ("A document needs at least one page… close its tab instead"), so nothing is closed without the tab-close confirmation.
- **Where:** `store.ts:450-455`, reached via Ctrl+A → Delete, the Organize button, or the trash icon on a 1-page document.
- **Impact:** skips the dirty-close prompt and the busy guard, never calls `commit()`, and deletes the history and OPFS bytes. One keypress loses all edits. **[probe]**
- **Fix:** route through the tab-close confirmation, make it undoable, and block it while a job runs.

#### RT-4 · 🟠 High · OPFS document bytes are never garbage-collected, including unredacted originals — ✅ Fixed

> **Status:** Startup sweep of orphaned `*.pdf` files in OPFS after the recovery decision. It only runs when this is the sole open Stapler tab (Web Lock), so another tab's documents are never deleted; without the Web Locks API it skips.
- **Where:** `AppShell.tsx:136-143` ("Start fresh" only clears the record); `opfs.ts` has no sweep.
- **Impact:** **privacy.** The pre-redaction original stays on disk after redact → export → close → Start fresh. Quota fills over time, and the quota error then blames "saved signatures". **[read]**
- **Fix:** a startup sweep of `*.pdf` not in the restored sources (keep model files). Also sweep on Start fresh.

#### RT-5 · 🟡 Medium · Closing a tab during a Home-screen import deletes the files being imported — ✅ Fixed
- **Where:** `import.ts:150` registers the source; `open-document.ts:58-76` adds the document only after all files finish.
- **Impact:** the new documents point at deleted sources. **[probe]**
- **Fix:** add a `pendingSources` set that GC treats as live.

#### RT-6 · 🟡 Medium · Opening a file wipes every document's undo; the Recents and paste paths skip the reset, so Ctrl+Z removes the new document — ✅ Fixed

> **Status:** `addDocument` records an "Open document" undo entry instead of wiping history; opening several files is one undo step, and every open path (drop, picker, Recents, paste) behaves the same.
- **Where:** `open-document.ts:81`, `HomeView.tsx:96-110`, `AppShell.tsx:224-251`.
- **Fix:** have `addDocument` push a history entry instead of `resetHistory()`, and make the three open paths behave the same. **[read]**

#### RT-7 · 🟡 Medium · The main open-files paths can't be cancelled and bypass the job model — ✅ Fixed

> **Status:** Opening files runs as a cancellable job (`runImportJob`) with a Cancel button — including on Home, which has no action bar — and a cancelled open adds nothing and frees what it stored.
- **Where:** `open-document.ts:46-50` (no signal).
- **Impact:** a 500 MB drop can't be stopped. This violates the CLAUDE.md "every long operation is cancellable" rule, and it is what makes RT-5 and RT-6 reachable.
- **Fix:** M5. **[read]**

#### RT-8 · 🟡 Medium · Long jobs overwrite edits made while they ran (§2.2 fix incomplete) — ✅ Fixed

> **Status:** Guarded at the user-facing call sites (grid keys, drag, thumbnail buttons, Organize, paste, stamp placement) via `src/ui/busy.ts`, not in the store — detect-blank legitimately deletes pages inside its own job.
Also covers the UI reviewer's UI-10.
- **Where:** `store.ts:757-787` (`replaceWithSource`), `:374` (`refreshBaseline`). `PageGrid`, `Thumbnail`, `OrganizePanel`, paste and `AnnotationOverlay` don't check `activeJob`.

## 5. Product gaps: how to make it better

These respect PLAN §1.1 non-goals: no in-place text editing, no password removal, no
PAdES, no accounts or telemetry, no pixel-perfect Office output.

### P1

- **GAP-1 · Make "Done" mean "works in the shipped build".** Add an extension-context e2e project, working CI, and a post-build network-host scan. This is the single change that would have prevented a third of this report (M4).
- **GAP-2 · The web twin is neither offline-capable nor installable.** It has no service worker and no web app manifest, yet it is branded "Offline PDF tools" and is the only path for locked-down machines and mobile. Add:
  - a same-origin precaching service worker with the list generated at build time (no Workbox CDN)
  - `manifest.webmanifest` with `file_handlers` + `launchQueue` ("Open with Stapler")
  - `share_target` (Android share sheet)
- **GAP-3 · The phone-width layout is poor, yet the landing pages drive phone traffic.** At 390px:
  - the trust chip is clipped
  - the icon rail takes about 15% of the width
  - the Compress options sheet overlaps the preview with text showing through
  - the ⌘K hint shows on touch devices

  Fix with a tools sheet below 600px, an opaque options sheet with correct z-order, hidden shortcut hints on `(pointer: coarse)`, and a mobile Playwright + axe pass.
- **GAP-4 · There is no landing page for the #1 search intent, "compress PDF to 100 KB".** DOC-07 already does target-size compression. Add 2–4 static pages (100 KB / 200 KB / 1 MB / custom) that deep-link into Compress with the target pre-filled via a URL parameter.

### P2

- **GAP-5 · Image target-size and resize output** ("photo must be under 20 KB" for portals). Reuse DOC-07's search loop for JPEG quality and scale, in PDF→Images and as a single-image mode.
- **GAP-6 · Missing standard page tools:**
  - **Grayscale / B&W:** also a strong compression lever for scans.
  - **Duplex interleave:** odd and even page scans, with reverse. Pure page-order logic.
  - **Repair:** re-save through the tolerant parser, with a report of what was fixed.
- **GAP-7 · Discoverability.** Add:
  - an `omnibox` keyword (no permission needed; confirm there's no install warning)
  - a "What's new" page on `onInstalled` with reason `update`
  - rail labels on hover and focus, grouped like the home page
- **GAP-8 · Release packaging is fully manual** (a 277-line checklist; zip made by hand, including sourcemaps). Add a `pnpm package` script (build ext / firefox / web → strip maps → zip → SHA-256) and a tag-triggered release workflow.
- **GAP-11 · Undo per document (G1) and an open-document ceiling (G2)** remain open from earlier audits. RT-2, RT-3 and RT-6 show how fragile the single global stack is; per-document stacks would remove a whole class of cross-document bugs.

### P3

- **GAP-9 · Storage resilience.** Request `navigator.storage.persist()` after the first session save or model download; show `storage.estimate()` in the trust panel; warn before recovery data is evicted.
- **GAP-10 · Read-aloud basics.** A local-only voice picker, sentence highlighting via the `boundary` event, and a remembered voice and rate (together with PLT-5).
- **GAP-12 · Honest trust chip.** Count disclosed downloads (PLT-16). Show what is stored locally (OPFS files, models, signatures) with a single "Clear all local data" button, which also addresses the RT-4 privacy concern.
