# Stapler — Independent Implementation Audit (2026-08-17)

This audit re-verifies every ticket in [`TICKETS.md`](TICKETS.md) against the actual
code, tests, and builds — not against that file's own self-reported evidence. It was
produced by four independent auditors, each covering a disjoint set of epics, plus one
dedicated adversarial bug-hunt pass over `src/core`, `src/ui`, `src/workers`, and
`src/platform`. Where a finding contradicts `TICKETS.md`, this document is the more
recent and more trustworthy source — it is derived from running the code, not from
reading a prior agent's claims about it.

## 0. Honest scope statement — what this audit does and does not cover

**Every ticket in `TICKETS.md` (all ~100, across all 15 epics) was assigned to one of
the four auditors**, so nothing was skipped at the ticket level. But "audited" here
means what each auditor could establish by reading code, running the existing test
suite, running builds, and — where cheap — writing small out-of-tree probes against the
real worker/export code. That is real verification, not a rubber stamp, but it has
firm limits. Being honest about them is the point of this section.

**Things this pass could NOT verify, for any ticket, regardless of auditor effort:**
- Anything requiring a real Chrome/Edge/Firefox browser load via the store UI, or an
  actual AMO/Edge Add-ons review (DIST-04's "passes review" clause).
- Rendering in Chrome's own PDFium viewer specifically — RED-06 and SGN-06 were checked
  against pdf.js and poppler instead, as documented proxies, not the literal AC.
- A real Lighthouse/Cloudflare Pages run for DIST-03 (only a local `vite preview` was
  measured, and those numbers are *below* the stated AC — see §1).
- QA-05's four-external-viewer manual checklist (Chrome viewer, Acrobat, macOS Preview,
  Firefox pdf.js) — this has always been a manual, human-run step; nothing here replaces
  it.
- OCR-01's actual model download over a real network connection (the sandbox has no
  network access to test the one deliberate exception to the zero-network invariant).
- HEIC decode/colour/orientation correctness (CNV-03, DOC-02) — no real `.heic` fixture
  exists in the corpus, so this remains genuinely untested end-to-end, exactly as
  `TICKETS.md` itself discloses.
- Wall-clock/perf ACs that depend on machine load and were not re-run here to avoid
  false regressions on a shared/contended machine: DOC-03's 1.5s/6s thumbnail budget,
  DOC-04's "300 pages at 60fps," CNV-01's "20 photos <10s," CNV-02's DPI-exact output
  dimensions and memory ceiling, F-05's 200ms-cancel/no-orphan-worker AC. Several of
  these were flagged as **untested anywhere in the committed suite**, not merely
  unre-run here — that distinction is called out per-ticket in §1 where it applies.
- Genuine UX/visual judgment calls: OPS-07's booklet fold order was checked by decoding
  page content and confirming the operator-level order is correct, but no auditor
  physically printed and folded a booklet; SCN-03's "must be visually convincing"
  screenshot AC is inherently a human judgment call.

**Known weak spots in what WAS covered, that deserve a second pass:**
- The automated bug-hunt (§3) was **one pass** over `src/core`, `src/ui`,
  `src/workers`, `src/platform`. It is not exhaustive — a single review pass finding 8
  (plus the 33 more found by the ticket auditors along the way) bounds the codebase's
  bug rate from below, not above. More bugs almost certainly exist, especially in files
  none of the five passes happened to open.
- No auditor reviewed **UI component visual/interaction correctness** as its own
  pass (only as a side effect of exercising specific tool flows) — a dedicated
  `ui-review`-style pass has not been run against this audit's findings.
- **i18n content correctness across all 11 locale files** (translation quality, not just
  the wiring bugs found in NFR-04) was not reviewed — only the loading/persistence
  mechanism was.
- **No adversarial re-verification of these auditors' own claims** happened yet — this
  is one round of independent-from-`TICKETS.md` auditing, but the four reports were not
  then cross-checked against each other or re-verified by a fifth pass. Treat findings
  here as strong leads, confirmed against real evidence in each case, but not beyond
  further challenge.
- Several "confirmed-done" verdicts in §2 carry named nits in the full per-agent
  transcripts (stale numbers, thin coverage on a secondary AC clause) that are folded
  into brief parentheticals here rather than spelled out — ask if you want the
  unabridged per-ticket detail for any specific one.

**Bottom line:** this is a real, evidence-based first pass across the whole ticket list,
not a sample. But it is one round, by agents working from source and tests without
browser-store access, hardware diversity, or a second adversarial check on each other.
The next round should target the "could not verify" list above and put a second set of
eyes on the weak spots, rather than re-treading the same ground.

**Baseline facts, measured independently by multiple auditors:**

- `pnpm test` → 56 files / 609 tests, 0 failures.
- `pnpm test:e2e` (full suite) → 86 passed, **2 failed**: `tool-flows.spec.ts` "cleanup:
  flatten background preserves text" (OPS-13) and `a11y-and-perf.spec.ts` "shortcut rows
  are keyboard operable" (DS-09).
- `pnpm check` → **fails on a clean master tree.** `check:tokens` and
  `check:invariants` both report 5 raw-colour `rgb()` literals in
  `src/core/text-diff-export.ts:21-28`, violating hard invariant #3. This means
  `TICKETS.md`'s own reproduction recipe (`pnpm check && pnpm test && pnpm test:e2e`)
  does not currently pass, which also breaks the ACs of F-01, DS-01, and DIST-05.

## 3. Remaining bugs found — verified open issues

### High — features that don't do what "Status: Done" claims

12. **`src/core/compress-plan.ts:275`** — Pages with sparse text (a short caption) and no
    embedded images are still routed to the raster pipeline and destructively
    rasterized, violating the invariant that non-image content stays byte-untouched by
    compression.
13. **`tests/e2e/tool-flows.spec.ts:601-603`** — CMP-02's assertion band is `>0.7 && <0.95`
    while the stated AC is 70–90% reduction — a 94% reduction (visually destroyed page)
    would still pass the test.
14. **`scripts/check-bundle-size.js:41-45`** — Selects the wrong build artifact (a
    0.26 KB entry stub) for the 900 KB gzip budget check, so the gate can never fail
    regardless of real bundle size.
15. **`src/background/service-worker.ts:19`** — `chrome.tabs.query({url:
    runtime.getURL('editor.html')+'*'})` silently returns `[]` without the `tabs`
    permission (verified on a real loaded build) — every toolbar click opens a new tab
    instead of focusing the existing one, in Chrome and Edge.
16. **`src/core/compare-export.ts:19`** + **`src/core/visual-diff-export.ts:117-119`** —
    The Compare tool's "Export Diff PDF" button calls `exportVisualDiff(docA, docB, [],
    options)` — an empty diff-results array — and wraps the re-render in a bare `catch
    {}` intended as a headless-test fallback. Reproduced: a 1-page, 612×792, all-white
    "diff" PDF is written and the export reports success.
17. **`src/core/pixel-diff.ts:11-13`** + **`ComparePanel.tsx:96-107`** — The "Sensitivity"
    slider is inverted: `threshold = (sensitivity/100)*765` means a *higher* percentage
    is *less* sensitive. At "100% Sensitivity" nothing is ever marked changed.
18. **`src/core/pixel-diff.ts`** (no dimension guard) — Indexes the second image buffer
    by the first image's length. A shorter second buffer reads as `undefined`, so
    `NaN > threshold` evaluates `false` and those pixels silently count as "unchanged"
    rather than erroring or flagging a size mismatch.
19. **`src/core/i18n/index.ts:54`** + **`src/ui/app.tsx:32`** — Locale selection is never
    persisted or restored. Choosing Arabic, then reloading, reverts to English. A
    `pt-BR` browser never auto-selects the `pt-BR` dictionary, and the English fallback
    dictionary is never loaded for non-English locales, so a missing translation key
    renders as its raw dotted name (e.g. `header.title`) instead of falling back.
20. **`src/ui/components/DropZone.tsx:110-120`** — A `<label tabIndex={0} role="button">`
    wraps the file `<input>`, producing an axe `nested-interactive` (serious) violation
    plus `aria-allowed-role`, on both the home route and first-run, in both themes.
    Never caught because the committed axe sweep excludes the home route.
21. **`src/core/pdf/accessibility.ts:196`** — `PDFString.of(altText)` writes one byte per
    JS character code. Non-Latin1 alt text (e.g. `日本語の写真 — café`) is corrupted on
    round-trip to garbage bytes plus a stray control character.
22. **`src/ui/tools/batch/BatchPanel.tsx:45, 61`** — A non-abort `showDirectoryPicker`
    failure (permission denied, `SecurityError`) is only `console.error`'d — the user
    clicks "select folder" and nothing visible happens.
23. **`src/core/shortcuts.ts:49`** — Redo is bound only to `mod+y`;
    `eventMatchesShortcut` requires `shift === false` with no alternate binding, so
    `⌘⇧Z`/`Ctrl+Shift+Z` — the macOS convention and DOC-06's own stated requirement —
    does nothing.
24. **`src/core/tools.ts:303`** (`shortcuts` tool entry) — Missing
    `worksWithoutDocument: true`. With no document open, `OptionsPanel` renders "Open a
    document to use this tool," making the entire keyboard-remapping UI unreachable.
    Reproduces the failing `a11y-and-perf.spec.ts:51` test.
25. **DIST-04 Firefox manifest transform** — `transformManifestForFirefox` adds the
    `tabs` permission (asserted by its own test), directly contradicting the ticket's
    claim that "permissions, CSP, and icons are untouched" between builds.
26. **`src/core/image.ts:71-73`** — Multi-page TIFF import decodes `ifds[0]` only. A
    12-page scanned TIFF silently imports as a 1-page PDF with no warning.
27. **`src/core/markdown-to-pdf.ts:51, 128`** — Any codepoint above 255 (CJK, Hebrew,
    etc.) is silently replaced with `?`; table cells are truncated at 30 characters with
    no ellipsis or warning. Both are silent data loss on export.
28. **No `LICENSE` file** — Referenced by `README.md`'s `[MIT License](LICENSE)` link,
    the store listing copy, and the in-app privacy/trust panel, none of which is backed
    by an actual license file in the repo root.

### Medium — test-quality issues and doc/code mismatches

29. **`src/core/pdf/linearize.ts:16`** — Stale comment claims "Most save sites pass
    `useObjectStreams: true`"; in fact none do (see DOC-05 above).
30. **`src/platform/file-system.ts:25-28`** — A test backdoor,
    `window.__mockClipboardImage`, is read before the real clipboard in *shipped

31. **`tests/unit/annotation-summary.test.ts` / `tests/unit/visual-diff-export.test.ts`**

33. **`docs/CONTRAST-AUDIT.md`** does not exist — DS-02's AC asks for "results recorded in

34. **`public/robots.txt`** advertises `/sitemap.xml`, which does not exist — masked in

35. **QA-03 / README** — Claims zero-network CI "runs automatically in CI on every

36. **DIST-04 `gecko.id`** — Still carries a `TODO(DIST-04): replace with the real ID`
    comment despite the ticket's prose claiming it's finalized.
37. **`tests/e2e/tool-flows.spec.ts:1292`** — A related but separately-reproduced
    failure: after setting a cleanup background colour and clicking "Apply to this

    distinct real failure in the scan-cleanup tool beyond OPS-13's flatten bug.
38. **`docs/TICKETS.md`** test-count claims are stale in multiple places (e.g. "196 unit
    tests across 13 files" vs. the real 609 tests / 56 files; "0.0% surgical" CMP-05
    projection vs. a re-measured 5.8%).
39. **`RELEASE_CHECKLIST.md`** — The per-release QA-05 checkbox ships pre-ticked `[x]` in
    the template itself, and the checklist's own gate ("`pnpm check` must be clean")
    cannot currently pass.

## 4. Recommended priority order

1. Fix the `pnpm check` failure (#raw-colour literals) — it's a one-file fix and unblocks
   the release-gate ACs for three other tickets.
2. Fix the redaction bugs (#1–7, #9–11) before this ships anywhere near real sensitive
   documents — these are the ones with actual privacy/legal consequences.
3. Fix the Compare-tool bugs (#16–18) — they currently produce a "successful" export
   that silently does nothing or shows wrong data.
4. Fix F-03 (#15) and DS-09 (#24) — both are simple, high-visibility UX breaks.
5. Everything else in §3 is lower urgency but should be tracked before a v1.0/v1.1
   release claim is made against the affected tickets.
